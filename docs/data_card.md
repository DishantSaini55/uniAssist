# Synthetic data card (Annex E)

| Field | |
|---|---|
| **Purpose** | Give the assistant a student database in the fixed Annex C schema that exercises every tool path: attendance at / one class below / above a threshold, failed course just under the pass mark, absent, detained, multiple backlogs, a backlog cleared by supplementary, CGPA exactly at the placement cut-off, students outside a rule's batch scope. **No real student data is used anywhere.** |
| **Generator** | Two stages. (1) *Identities* (id, name, programme, batch, semester, CGPA) are the seed in `data/seed/students_seed.csv`. They came from the repository's original AI-drafted dataset; the model name/version and prompt for that draft were **not recorded in the repo** (`TEAM TO FILL IN` if known). (2) *Everything derived* (attendance, results, backlogs, the extra courses and edge-case students) comes from `scripts/generate_students.py`: deterministic, fixed seed `20261006`, **zero LLM calls**, so the CSVs are reproducible byte for byte. An LLM identity generator is provided (`scripts/generate_students_llm.py`: local Ollama, temperature 0.7, at most 3 calls with validation-error feedback) but its output is **not** part of the shipped data. |
| **Prompts** | `docs/prompts.md` (verbatim prompt used by the LLM generator script). |
| **Schema enforcement** | SQLite `CHECK` constraints and foreign keys (`app/db.py`, Annex C columns unchanged); row-level validators and cross-table checks in `app/validation.py`; Pydantic models with retry-on-error for the LLM path. The loader skips invalid rows and reports them (`--strict` aborts instead). |
| **Row counts and distributions** | 36 students: B.Tech CSE 2023 ×12, CSE 2024 ×8, ECE 2023 ×8, ECE 2024 ×8. 8 courses (4 per programme, incl. Mathematics `MA201`/`MA251`, credits 4). 144 attendance rows (one per student-course): min 60.0 %, median 90.0 %, max 97.8 %. 145 results rows (144 REGULAR + 1 SUPPLEMENTARY): 134 PASS, 8 FAIL, 2 DETAINED, 1 ABSENT; passing totals 44-87 (median 69). CGPA 6.49-9.95 (median 8.20). Active backlogs: 0 ×28, 1 ×6, 2 ×2. |
| **Edge cases included** | Attendance exactly 75 %: **S1001/CS201** (40 held, 30 attended), S1017/EC202. Exactly 80 %: **S1010/CS201**, S1018/EC201. One class below 75 %: S1002/CS201 (72.5 %), S1021/EC203. One class below 80 %: **S1003/CS203** (77.5 %), S1007/CS202. Failed with marks just below the 40 pass mark (39/100): **S1003/CS201**, S1004/CS202, S1006/CS201 and CS202. Absent: **S1005/CS203**. Detained: **S1005/CS201**, S1002/CS201. Multiple backlogs: **S1006** (2), S1005 (2). Backlog cleared via supplementary: **S1036/CS202**. Mathematics fail (supplementary-eligible): **S1007/MA201**. CGPA exactly at the placement cut-off 6.50: **S1033**; 6.49: S1034; strong CGPA but a backlog: S1035. 2024-batch students (e.g. S1009) fall outside the placement circular's batch scope. Reserved judge ids `S9000-S9999` and course prefix `JDG` are never used. |
| **Validation results** | `python scripts/validate_data.py` -> `VALIDATION PASSED`, 0 errors, 0 warnings (checks: Annex C columns present; id format; ranges; attended <= held; total = internal + external and <= max; PASS/FAIL consistent with the 40 % pass mark; ABSENT = 0 marks; DETAINED = 0 external marks; foreign keys; `active_backlogs` equals the number of courses whose latest attempt is not a pass; every rule cites an existing Source Register document and a non-empty clause). Unit tests: `tests/test_data_kit.py`. |
| **What the LLM got wrong** | Found by the consistency checks in the original AI-drafted data and fixed in the generator: (1) `active_backlogs` disagreed with the results table (S1002 DETAINED and S1005 DETAINED + ABSENT but both showed 0 backlogs); (2) no supplementary attempt existed, so "latest attempt wins" could not be tested; (3) no Mathematics course although the guide's example asks about it; (4) no placement CGPA boundary student; (5) session ordering: `2026-JUL` sorts before `2026-MAY` alphabetically, which made a cleared backlog look uncleared until sessions were compared chronologically (caught by `tests/test_tools.py::test_latest_attempt_wins_for_backlogs`). |
| **Known limitations** | Every student takes the same 4 courses of their programme regardless of semester (a deliberate simplification: one course catalogue). Marks and attendance outside the injected edge cases are uniform random, not realistic distributions. Names are generated Indian names only. 36 students is enough to exercise logic, not to test scale. Attendance is a single snapshot per course (no per-month history). |
